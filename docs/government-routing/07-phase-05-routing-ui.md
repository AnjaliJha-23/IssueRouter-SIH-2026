# Phase 5: Routing UI

## Objective
Upgrade the `RoutingModal` to support assigning a challenge to multiple universities concurrently, setting a strict response deadline, and allowing manual fallback search across the full directory.

## Scope
- Overhaul `RoutingModal.jsx` to switch from a single-select radio pattern to a multi-select checkbox pattern.
- Add a deadline configuration panel.
- Implement a client-side search against the full active university directory for manual assignment.
- Update the parent `GovDashboard.jsx` to handle the new confirmation signature.

## Files Modified
- `frontend/src/components/ui/RoutingModal.jsx`: Fully rewritten.
- `frontend/src/pages/GovDashboard.jsx`: Updated `handleConfirmRoute` to pass the updated parameters (`org_ids`, `deadline`).

## Implementation Details
1. **Multi-Select**: The matches generated by the Phase 3 backend are now rendered with checkboxes. The component auto-selects the top 3 semantic matches by default.
2. **Deadline Configuration**:
   - Added a dropdown offering standard SLAs (3 Days, 7 Days, 14 Days) and a "Custom Date" fallback.
   - The UI automatically calculates the exact ISO 8601 timestamp representing 23:59:59 of the target day.
3. **Manual Directory Search**:
   - Added a search input that filters through `allUniversities` (fetched via `GET /api/universities/?status=ACTIVE`).
   - Universities already present in the AI suggestions are filtered out of the search results to prevent duplication.
   - Clicking "Add" adds the university to the `selectedOrgIds` state and renders it distinctly at the bottom of the list.
4. **Validation**: The "Confirm & Route" button is disabled if zero universities are selected, or if the "Custom Date" option is selected but no date has been picked.

## Note on API Compatibility
By changing `body: JSON.stringify({ org_id: orgId, note })` to `body: JSON.stringify({ org_ids: orgIds, deadline, note })` in `GovDashboard.jsx`, the frontend is now technically out of sync with the *current* Phase 4 backend `/route` endpoint. **This is intentional.** The backend will be upgraded to support `RoutingBatch` and multiple `RoutingInvitation`s in Phase 6.
